# Create ticket workflow
LLM identify if user wants to submit a ticket or not. LLM determines ticket type and collects user information. Workflow engine determines what questions to ask depending on ticket type.

Flow:
User message
    ↓
LLM identifies if user wants to submit ticket
    ↓
LLM identify ticket type
    ├── software_request
    ├── hardware_request
    └── incident_ticket
    ↓
Load corresponding questionnaire configuration
    ↓
LLM extract information from user's message and user's personal data
    ↓
workflow engine check what information is missing
    ↓
workflow asks for missing information
    ↓
all information collected
    ↓
show ticket summary to user
    ↓
waiting for user's confirmation
    ↓
call create_ticket tool

LLM output:
{
 "intent":"...",
 "ticket_type": "...",
 "confidence": 0.96,
 "extracted_fields":{
	"software_name":"...",
        "device_name":"...",
        "business_justification":"..."
}

}

Write yaml files for different types of request:
backend/
└── app/
    └── workflows/
        └── ticket/
            ├── engine.py
            ├── state.py
            └── questionnaires/
                ├── software_request.yaml
                ├── hardware_request.yaml
                └── incident_ticket.yaml
hardware_request.yaml:
ticket_type: hardware_request

fields:
  - name: requested_item
    question: What hardware item do you need?
    required: true

  - name: business_justification
    question: Why do you need this hardware?
    required: true

  - name: urgency
    question: How urgent is this request?
    required: true

  - name: delivery_location
    question: Where should the hardware be delivered?
    required: true

software_request.yaml:
ticket_type: software_request

fields:
  - name: software_name
    question: What software do you need?
    required: true

  - name: business_justification
    question: How will you use this software?
    required: true

  - name: device_name
    question: Which device should it be installed on?
    required: true

  - name: manager_approval
    question: Has your manager approved this request?
    required: true

incident_ticket.yaml:
ticket_type: incident_ticket

fields:
  - name: issue_description
    question: Briefly describe the issue.
    required: true

  - name: affected_service
    question: Which application or device is affected?
    required: true

  - name: started_at
    question: When did the issue begin?
    required: true

  - name: impact
    question: How is this issue affecting your work?
    required: true

  - name: error_message
    question: Do you see an error message?
    required: false

Save workflow state in table workflow_runs so that workflow engine can determine what information is missed by comparing questionnaire and current collected information.
